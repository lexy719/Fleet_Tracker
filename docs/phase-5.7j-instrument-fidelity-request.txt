FleetOS — Phase 5.7J: Operational Instrument Fidelity, Visual Depth & Living Composition
(Request as supplied by the user, 2026-10-07. Structure and rules preserved; formatting normalised.)

Mission. 5.7I established the correct visual architecture — preserve it; do NOT return to generic panels. Foundation: one anchor strip; one instrument per lead; supports as annotations/facts/consequences; Driver = time; Vehicle = the physical combination; Route & Stops = progression + trade-offs; Documents = operational dossier; Restrictions = applicability logic; Attention-first base; real recorded road geometry; explicit data-honesty language; scalable semantic architecture. 5.7J is not an architecture reset: make the instruments materially richer, more believable, more spatial, more alive and more finished. The remaining problem is fidelity (e.g. the truck reads as rectangles with wheels and cargo boxes).

1 Preserve: anchor strip, lead instrument, active lenses, semantic groups, support annotations, spatial questions, attention-first base, honesty states, pending-change bar, exact Esc/history, real road geometry, FleetOS map styling. Do not reintroduce generic cards, repeated headers, card-per-lens, dashboard grids, giant metric tiles, random geometry, decorative charts.
2 New bar: "Does each instrument feel like a believable professional tool designed for this problem?" A correct abstraction with placeholder-grade rendering is not finished.
3–5 Vehicle (highest priority): keep the side elevation; replace with a convincing technical representation reading as tractor + chassis + fifth wheel + semitrailer. Include cab silhouette, windscreen, roof, bumper, wheel arches, chassis, fuel tank/side equipment, fifth-wheel relationship, trailer front, curtain-side body, rear doors, underrun bar, five axles, realistic wheels with tyre/rim, grounded baseline. Elegant schematic technical drawing — not cartoon, not CAD clutter, not a photo. Proportions driven by facts (16.50 m, 4.00 m, 5 axles, ~13.6 m trailer).
6–7 Cargo as a genuine load plan: slots, occupied/empty, unload sequence, destination grouping, optional weight grouping, ADR/temperature, first-drop goods near the door. Grouping, subtle labels, sequence markers, boundaries, loading direction — not coloured bricks. A cutaway/load-plan strip is acceptable if clearer.
8 Vehicle + restriction: facts bind to parts — height threshold line (limit vs actual), first axle pointer, unknown as dashed dimension "? ≥ 1.10 m required · not recorded", counted axles highlighted, weight "estimated combination 27.6 t vs threshold 3.5 t" attached to the vehicle.
9 Vehicle reacts to the question (location, capacity, restriction, maintenance, assignment): same object, different emphasis (restriction → dims/axles; load → load plan; fuel/range → reading/provenance + route relation).
10–12 Driver: deepen the time axis (actual vs planned vs uncertain, thresholds, stop/window relations, note anchoring, now hierarchy, rhythm). One continuous day: past, now, committed future, uncertain future via line/opacity/texture. Supports originate from the moment they affect (e.g. 10:32 Santarém ↳ Vehicle ≈12% fuel ↳ Route & Stops 18 min margin).
13–16 Route & Stops: preserve the strip; add hierarchy and depth as coordinated layers of one journey (route progress/km; driver legal/break window; vehicle range; stops; road intelligence; delivery windows) — not six dashboards. Stops as objects: on-route, detour, selected, recommended, infeasible, unknown suitability; spurs connected to the strip; detour spatially evident. Keep the comparison grid; refine hierarchy (recommendation / operator choice / infeasible); avoid spreadsheet aesthetics.
17–19 Documents: preserve concept; improve fidelity. CMR paper more authentic (spacing, field grouping, serial/reference, stamps/status, signature/issue areas; no fields production does not support). Snapshot-vs-current legible at a glance with subtle diff language ("22 → 24 pallets").
20–22 Restrictions: preserve "Does it apply? ✓/✕/?". Make logic causal: facts → predicates → exception → verdict → operational consequence, visibly related. Unknown stays first-class: what is missing, where it comes from, what resolves it, what stays blocked.
23–24 Attention: preserve severity groups; add age, affected job/resource, next action, spatial relevance, consequence if ignored. Feel alive: smooth enter/leave, focus affecting the map, geographic emphasis on hover, selection opens the relevant instrument. Not a notification center.
25–27 Living composition: transitions should feel like the same world reconfiguring. Morph meaningful objects (Driver → Route & Stops: next-stop marker becomes the selected stop; Vehicle → Restrictions: dimensions/axles persist as the condition carries across; Documents → Transport Overview: dossier status compresses into the document region). Preserve perceptual continuity for F-07, D-14, AA-42-ZP, CMR-4217, RI-042.
28–30 Map: same persistent renderer; camera and geometry move together (no resize-then-snap, no overlay flicker); integrate further (labels, road hierarchy, travelled vs remaining, restrictions, simulated position, selected stop, alternative); overlay hierarchy follows the question.
31–32 Transport Overview: the central narrative of one transport — where it started, where it is, what happens next, what threatens it, what the operator must decide; not a grid of mini-cards.
33–34 Depth from relationships (layering, annotations, alignment, continuity, provenance, temporal structure, cause → consequence), not shadows/glass/gradients/3D. Physical things physically: vehicle form, load plan, paper, real road, stops on progression, time, logic + segment.

Cross-instrument links: first-axle missing → Vehicle focused on first axle; CMR differs → diff takeover; break before 10:50 → Driver focus; Santarém selected → Route & Stops focus. Temporary focus states (not modals): related fact primary, unrelated fades, map segment remains; Esc restores.
